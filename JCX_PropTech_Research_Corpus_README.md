## Recommended website build order

1. Import `discovery_universe` for broad search, then join qualified profiles from `atlas_entities`, claims, assertions, relationships, outcomes, standards and sources; keep the legacy master for audit lineage only.
2. Resolve the generated editorial queue—especially 22 tier conflicts, 52 entities without a verified canonical domain and product/parent relationships—before public ranking or lifecycle heatmaps.
3. Build the lifecycle × technology map, organization profiles and evidence drawers.
4. Add compare, regional, outcome and failure views.
5. Keep JCX-specific observations in a private client layer unless publication is approved.
6. Add an editorial review queue, freshness dates and corrections before calling the atlas “live.”

## Regenerating the data

Run:

```bash
python3 scripts/build_proptech_master_dataset.py
```

The script reads the eight qualified-core source CSVs, preserves exact source assertions, merges only reviewed identity aliases with collision safeguards, generates normalized entity/claim/relationship tables, imports outcomes, standards and dated discovery snapshots, and produces the full-corpus source register and manifest. It leaves mixed tiers and unsupported status dates unresolved instead of silently selecting a public value.

## Publication warning

Before publishing any profile, re-open its important sources and confirm current identity, status, product, ownership, geography and claim wording. Preserve “reported,” “estimated,” “potential,” “up to,” “avoided” and similar qualifiers. Funding, accelerator membership, a live website and a customer logo are not outcome evidence.
